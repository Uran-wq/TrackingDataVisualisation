# DataLight — визуализация VR-трекинга

**English:** [README.md](README.md) (default)

Разбирает незнакомый файл с данными VR-трекинга и показывает их тремя способами:

1. **Статистика движения** — скорость и перемещение во времени, длины траекторий, сводная таблица.
2. **3D-траектории** головы, левой и правой руки — статичный PNG плюс интерактивный HTML.
3. **Интерактивный 3D-вьюер** — воспроизведение в реальном времени с моделью шлема и скелетами кистей из 26 суставов.

## Формат входных данных

`trackingData_20260505_165740.txt` (258 МБ), UTF-8, **JSON Lines**:

- **Строка 1** — метаданные: `notice`, `timeStampNs`, `cameraExtrinsics`, `cameraIntrinsics`.
- **Строки 2–21788** — 21 787 записей трекинга: `predictTime`, `appState`, `Head`, `Hand` (26 суставов на кисть), `Body` (24 сустава), `timeStampNs`, `Input`.

**Подводный камень, который ломает наивный парсинг:** в строках поз (`Head.pose`, `…HandJointLocations[].p`) **запятая — и десятичный разделитель, и разделитель значений**: `"-0,08517717"` это число `-0.08517717`, а вся поза — 14 токенов через запятую = 7 чисел (`x,y,z,qx,qy,qz,qw`). Обычный `float()` падает; значения нужно склеивать попарно (`src/data_loader.py:parse_locale_numbers`). Поля `va`/`wva` смешивают запятые с экспонентной записью `E±`, из-за чего границы токенов однозначно не восстановить без спецификации — они не используются.

Время берётся из `timeStampNs` (монотонные наносекунды). У `predictTime` непроверенные единицы — он не используется.

Камерная запись `CameraRecord_20260505_165740.mp4` (199 МБ) **не используется** — синхронизация с видео была необязательным подходом из задания.

### Входные файлы не в git

Оба входных файла больше лимита GitHub в 100 МБ на файл, поэтому они добавлены в `.gitignore`. **Положите оба файла в корень репозитория** (рядом с этим README) перед запуском.

## Установка

Проверено на Python 3.14 (подойдёт любой свежий 3.10+):

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

Из корня репозитория — одна команда:

```bash
python -m src.main --input trackingData_20260505_165740.txt --output output
```

Оба аргумента необязательны (здесь показаны значения по умолчанию). Команда печатает сводку и записывает:

| Файл | Содержимое |
|---|---|
| `output/motion_statistics.png` | Скорость, перемещение, длина траектории, сводная таблица |
| `output/trajectory_3d.png` | Статичные 3D-траектории головы и рук (пример для README) |
| `output/trajectory_3d.html` | Интерактивные 3D-траектории (самодостаточный файл) |
| `output/viewer/` | Бандл интерактивного 3D-вьюера (открыть `index.html`) |
| `output/summary_stats.json` | Машиночитаемая сводка напечатанных чисел |

## Интерактивный 3D-вьюер

Откройте `output/viewer/index.html` в любом браузере — без сервера и без сборки (three.js r147 и все ассеты лежат в репозитории в `viewer/lib/`; страница не грузит ничего из сети).

- **Голова:** стилизованный шлем, ориентированный по записанному кватерниону головы (визор = проверенная ось взгляда), с локальной тройкой осей XYZ.
- **Кисти:** все 26 суставов в виде сфер, соединённых костями, связность которых проверена по данным (см. наблюдения ниже); красный — левая, зелёный — правая, как на фигурах.
- **Управление:** пауза/воспроизведение, скорость 0,25×–4×, перемотка таймлайна, перетаскивание — вращение, правая кнопка — панорама, колесо — зум, сброс камеры.
- **Пропуски:** неактивная в данных кисть скрывается ровно на эти кадры — позиции никогда не интерполируются.

## Тесты

```bash
pip install pytest
python -m pytest tests -q
```

37 тестов покрывают хрупкие места: парсинг десятичной запятой (на реальных значениях из файла), преобразование меток времени, извлечение позы головы и рук (позиции, кватернион, полные массивы суставов), пропуски неактивной руки, математика скорости/длины при нулевом `dt`, битый/пустой вход и экспорт вьюера (даунсемплинг, base64-полезная нагрузка, сборка бандла). Команда из раздела «Запуск» прогнана end-to-end на полном файле 258 МБ.

## Ключевые наблюдения

Все числа ниже получены запуском выше (единицы — исходные единицы файла — **вероятно метры, не подтверждено**).

- **Длительность/частота:** 21 787 записей за 242,5 с; медианный интервал 11,1 мс (≈89,9 Гц), диапазон 6,2–67,4 мс; отрицательных приращений времени нет.
- **Голова:** длина траектории 15,9; средняя/медианная/максимальная скорость 0,066 / 0,060 / 0,481; укладывается в коробку 0,21 × 0,09 × 0,26 рядом с началом координат.
- **Левая рука:** длина траектории 17,4; скорости 0,072 / 0,043 / 1,364; активна во всех 21 787 записях.
- **Правая рука:** неактивна первые 0,81 с и последние 0,76 с (135 записей всего — реальные пропуски трекинга, на графиках разрывы, никогда не интерполируются). Длина траектории 84,2 при средней скорости 0,351 и максимуме 5,12.
- **Правая рука заметно дрожливее левой:** медианный шаг от кадра к кадру 3,8 мм против 0,5 мм (левая) и 0,7 мм (голова); 96 кадров превышают 1 ед/с, включая скачки ~5 см за один кадр сразу после активации трекинга на t ≈ 0,8 с. Длина её траектории завышена шумом и не читается как осмысленное перемещение.
- **Пространственная раскладка:** голова около начала координат; обе руки лежат при более отрицательном y, чем голова (голова y ≈ −0,09, руки ≈ −0,38…−0,44), то есть руки ниже головы — но соглашение о осях не доказано, поэтому оси выведены ровно как в файле.
- **Ориентацию головы можно использовать:** применённый к записанной позе кватернион головы (x,y,z,w, голова→мир) направляет ось взгляда (локальный −Z) на записанные позиции рук в **100% кадров**; альтернативный порядок w первым помещает руки «за спину лица» в каждом кадре и отвергнут.
- **Топология кисти подтверждена:** 26 суставов соответствуют порядку OpenXR — 21 предположенная связь пальцев/ладони со временем остаётся жёсткой (отн. СВ длины ≈ 0,013), тогда как контрольные пары через пальцы меняются на 0,1–0,76. Вьюер рисует ровно эти 25 костей.

## Допущения и ограничения

- **Позиция руки = сустав 0** (первая запись `HandJointLocations`) из 26 — представительная точка руки в статистических фигурах. В файле нет имён суставов; порядок OpenXR-стиля *подтверждён* тестом жёсткости выше, но отдельные суставы по-прежнему безымянны.
- **Единицы/оси не пересчитываются.** Позиции укладываются в < 1 единицы от начала координат у головы — это похоже на метры, но файл никогда не указывает единицы и ориентацию осей. Никаких смен осей или знаков нигде нет; на фигурах оси подписаны «source units».
- Скорости — конечно-разностные оценки (`‖p[i] − p[i−1]‖ / dt`) и наследуют шум трекинга, особенно у правой руки.
- **Соглашение об ориентации головы выведено, а не документировано:** вьюер отрисовывает кватернионы `Head.pose` как x,y,z,w, голова→мир, лицо — локальный −Z. Эта раскладка проходит тест выше (100% кадров), но сам файл соглашение не определяет.
- `va`/`wva` (неоднозначное кодирование запятыми/экспонентой) и `predictTime` (неизвестные единицы) сознательно не используются.
- Поведенческие интерпретации («человек сделал X») не предпринимаются — три отслеживаемые точки допускают только геометрические/временные утверждения.

## Сложности

1. **Десятичная запятая внутри строк JSON** — JSON-оболочка парсится нормально, но каждое значение позы нужно склеивать попарно перед `float()`. Решено одной тестируемой функцией; в юнит-тестах — реальная поза из файла.
2. **Неоднозначное кодирование `va`/`wva`** — запятая-разделитель и запятая-десятичный сталкиваются (`"0,0,0,370,054…"`). Без спецификации разбиение неоднозначно, поэтому поля исключены, а не угаданы.
3. **Пропуски неактивной руки** — у 135 кадров правой руки нет позиции. Они оставлены как NaN: на графиках линия рвётся, расчёты скорости/длины пропускают граничные отрезки, позиции никогда не выдумываются.
4. **Шум правой руки** — всплески до 5,1 ед/с реально есть в данных, это не баг парсинга; вместо сглаживания они количественно описаны выше.
5. **Файлы 258 МБ и 199 МБ против лимита GitHub в 100 МБ** — исключены через `.gitignore`, размещение описано здесь.
6. **Недокументированные соглашения поз** — порядок компонент кватерниона, handedness и порядок суставов в файле никогда не указаны. Каждое решено данными (направление «лицо—руки», жёсткость костей), а не принято на веру; тесты описаны в наблюдениях выше.
7. **Интерактивный вьюер без тулинга сборки** — релиз должен открываться сразу после клонирования: three.js r147 (UMD) и OrbitControls лежат в `viewer/lib/`, полезная нагрузка воспроизведения выгружена в base64-`Float32Array` в `data.js`, поэтому `output/viewer/index.html` работает из `file://` без npm, бандлера и локального сервера.
